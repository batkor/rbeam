# rbeam

[English](README.md) | [Русский](README.ru.md)

P2P-инструмент для передачи файлов и каталогов со своим (self-host) сигнальным
и relay-сервером. Трафик шифруется end-to-end ключом, выведенным из короткого кода.
Бинари: `rbeam` (клиент) и `rbeam-relay` (сервер).

## Что делает

Передаёт файлы и каталоги между двумя клиентами по короткому цифровому коду. Сервер
только помогает клиентам найти друг друга и проксирует трафик, когда прямое соединение
невозможно; сами данные он не хранит.

## Транспорты

Отправитель запускает три транспорта параллельно. Побеждает тот, где первым установился
реальный канал, остальные гасятся:

- **RADAR** — обнаружение в локальной сети через UDP-broadcast, затем прямое TCP-соединение.
- **DIRECT** — сервер сообщает получателю адрес отправителя, после чего клиенты соединяются
  напрямую.
- **PROXY** — трафик идёт через сервер, если прямой путь недоступен.

## Достоинства

- **Приоритет локальной сети** — по возможности данные не покидают LAN.
- **Автоматический fallback** — если прямое соединение не удаётся, работает relay.
- **Сервер не хранит данные** — это сигналинг и прокси, а не хранилище.
- **End-to-end шифрование** — SPAKE2 по коду, затем ChaCha20-Poly1305; сервер видит
  только шифротекст.
- **Self-host** — можно собрать свой экземпляр со своим хостом и портом.
- **Безопасный приём** — запись только в выбранную директорию с валидацией путей.

## Конфигурация self-host

Адреса вшиваются при сборке через `.cargo/config.toml`:

```toml
[env]
SERVER_BIND = "0.0.0.0:80"   # локальный адрес сервера (bind)
SERVER_ADDR = "host:80"       # публичный адрес, куда подключаются клиенты
```

Скопируйте `.cargo/config.toml.example` в `.cargo/config.toml` (он в `.gitignore`)
и укажите свои значения.

```sh
cargo build --release

./target/release/rbeam-relay                 # запуск сервера
./target/release/rbeam --path /path/to/send  # отправитель (печатает код)
./target/release/rbeam                       # получатель (ввести код)
```

Получатель спрашивает, куда сохранять данные; директории по умолчанию нет.

## Использование

Отправитель:

```sh
cargo run -- --path /tmp/fixture
```

Он печатает код вида `123456-ABCDEF` (публичный nameplate + секрет).

Получатель:

```sh
cargo run
# ввести код, затем подтвердить/выбрать директорию для сохранения
```

Опции:

- `--out <dir>` — директория для сохранения (иначе спросит интерактивно).
- `--override` — заменять существующие файлы (по умолчанию: пропуск с логом).
- `--transport <all|radar|direct|proxy>` — принудительно один транспорт отправителя
  (по умолчанию `all`).

Получатель всегда пробует все три транспорта; отправителя можно ограничить через
`--transport`.

## Docker (разработка)

```sh
docker compose build
docker compose up -d

docker compose exec client1 bash    # cargo run -- --path /tmp/fixture
docker compose exec client2 bash    # cargo run
```

Образы не собирают бинарь заранее; компиляция происходит при `cargo run` в контейнере.
`.cargo/config.toml` монтируется в каждый контейнер, поэтому адреса из `env!` доступны.

## Безопасность

- Код состоит из двух частей: публичный **nameplate** (по нему сервер ищет сессию) и
  **секрет** (на сервер не отправляется). Секрет используется в SPAKE2 для вывода
  сильного сессионного ключа; далее данные шифруются и аутентифицируются
  ChaCha20-Poly1305.
- Неверный секрет не проходит key confirmation — соединение рвётся.
- Получатель считает отправителя недоверенным: пути валидируются и ограничиваются
  пределами `--out`; абсолютные пути, `..`, буквы дисков и NUL отвергаются.
- Существующие файлы пропускаются, если не указан `--override`.
- Симлинки и спецфайлы на отправителе пропускаются.
- Сервер релеит только шифротекст. Короткий секрет ограничивает online-перебор,
  поэтому используйте код в доверенной сети.
